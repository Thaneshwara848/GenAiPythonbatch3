# AI Prompt: Build a Full-Stack Employee Management System

Act as a **Senior Python Full-Stack Developer, FastAPI Expert, MySQL Database Engineer, and Professional UI/UX Designer**.

I want to build a complete, modern, responsive, and fully functional **Employee Management System** web application from scratch.

I am learning full-stack development, so explain everything step by step with simple, beginner-friendly explanations.

I will manually create the project files, copy the code, install the dependencies, configure MySQL, and run the application using VS Code on Windows.

## 1. Technology Stack

**Backend:**
- Python 3.11+
- FastAPI
- Pydantic for data validation
- MySQL Database
- mysql-connector-python
- REST APIs
- HTTPException for error handling
- Python logging
- python-dotenv

**Frontend:**
- HTML5
- CSS3
- JavaScript (Vanilla JS)
- Fetch API for backend integration
- Font Awesome icons
- Modern responsive dashboard

**Restrictions:**
- Do not use React, Angular, Django, or SQLAlchemy.
- Keep the code simple and beginner-friendly.
- Use direct MySQL queries with parameterized SQL.
- Provide complete runnable code without placeholders.

## 2. Database Design

Create a MySQL database named `employee_db`.

Create an `employees` table with these fields:

| Field | Data Type | Description |
|---|---|---|
| id | INT | Primary key, auto increment |
| name | VARCHAR(100) | Employee full name |
| age | INT | Employee age |
| email | VARCHAR(150) | Unique email address |
| phone | VARCHAR(15) | Contact number |
| department | VARCHAR(100) | Employee department |
| designation | VARCHAR(100) | Job title |
| salary | DECIMAL(12,2) | Monthly salary |
| joining_date | DATE | Joining date |
| status | VARCHAR(20) | Active or Inactive |

Provide the complete MySQL database creation script.

## 3. Backend REST API Requirements

Develop the following REST API endpoints using FastAPI:

| Method | Endpoint | Functionality |
|---|---|---|
| GET | `/` | Application health message |
| POST | `/employees` | Add a new employee |
| GET | `/employees` | Display all employees |
| GET | `/employees/{id}` | Search employee by ID |
| PUT | `/employees/{id}` | Update employee details |
| DELETE | `/employees/{id}` | Delete employee by ID |
| DELETE | `/employees` | Delete all employees |
| GET | `/employees/search` | Search employees by name |
| GET | `/employees/department/{department}` | Filter by department |
| GET | `/dashboard/stats` | Dashboard statistics |

Ensure static routes such as `/employees/search` are defined before dynamic routes where required.

All endpoints must connect to the MySQL database.

## 4. Pydantic Validation

Implement appropriate validation:

- Employee name cannot be empty.
- Age must be between 18 and 65.
- Email must have a valid format.
- Email must be unique.
- Salary must be greater than zero.
- Department and designation are mandatory.
- Joining date must be a valid date.
- Employee status must be Active or Inactive.

Use Pydantic models and meaningful validation error messages.

## 5. Exception Handling

Implement proper error handling for:

- Employee not found — HTTP 404.
- Invalid input — HTTP 422.
- Duplicate employee email — HTTP 409.
- Database connection failures — HTTP 503.
- Unexpected server errors — HTTP 500.

Do not expose database credentials or sensitive exception details to the frontend.

Use a professional blue, white, and dark-gray color theme.

## 7. Frontend and Backend Integration

Use JavaScript Fetch API to connect the frontend with FastAPI.

Examples:

- Submit Add Employee form → POST `/employees`
- Load employee table → GET `/employees`
- Edit employee → PUT `/employees/{id}`
- Delete employee → DELETE `/employees/{id}`
- Search employee → GET `/employees/search?name=...`
- Load dashboard cards → GET `/dashboard/stats`

Update the employee table and dashboard statistics automatically after successful CRUD operations without refreshing the browser.

Handle network failures, validation errors, and server errors clearly.

Render user-entered data safely to avoid HTML injection.
